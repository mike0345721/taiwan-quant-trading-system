# CRU-21 offline source closure engineering

This directory is an independent cloud engineering artifact. It changes no
repository checkout, native guard, product pin, runtime, permission or credential.
It never imports, links or evaluates a product or vendor module, starts a server,
reads environment/data/vault files, or uses a network/CI/MSI connection.

`closure-tool.mjs` has two separate claims:

- **Inventory**: exactly the approved 356 names, exact bytes/size/SHA256/Git blob
  from the separately hash-pinned materialization receipt. Binary and CRLF bytes
  are base64 encoded without decoding/re-encoding their text.
- **Graph**: the entry-reachable ESM static requests obtained only by constructing
  `vm.SourceTextModule`. No `link()` or `evaluate()` is called. Dynamic/CommonJS
  hints are conservative unsupported findings. Runtime assets, external data,
  packages and native libraries are outside this proof. `dependencyClosureProven`
  is always false; an inventory PASS never becomes a full dependency/runtime PASS.

## Commands

```sh
node --experimental-vm-modules --test --test-isolation=none --test-reporter=tap closure-tool.test.mjs
node --experimental-vm-modules closure-tool.mjs build SOURCE_ROOT SOURCE_MATERIALIZATION_JSON BASELINE_PATHS_JSON NEW_OUTPUT_ROOT
```

Metadata filenames must be `source-materialization.json` and
`baseline-normal-paths.json`; their raw bytes must match the fixed digests.
Output must be a new directory outside source. Existing outputs are rejected,
not overwritten. Artifact JSON files are compact `JSON.stringify(value)` plus LF.
The embedded `manifestSHA256` hashes the compact manifest without that LF.

## Scope and safety

Source reads and output writes require Linux `/proc/self/fd`, held directories
and `O_NOFOLLOW` for every component/leaf. Aliases, hardlinks, traversals,
case-colliding paths, environment/vault/data/vendor paths and unapproved source
roles are rejected. Output's parent is held before its directory is created;
symlink parents cannot redirect a write. Sizes are bounded and source changes
during read reject. This is not a Windows filesystem adapter or runtime launcher.

Synthetic fixtures test deterministic bytes, binary/CRLF, wrong version/hash,
missing/duplicate paths, traversal, symlink/hardlink aliases, output collision,
redirected output parents, package tampering and poison source that must not run.
No source/vendor module is executed by those tests. The initial test receipt
contains 28 PASS/1 FAIL because the case-collision fixture used a top-level path
already rejected by the source-role rule; the corrected fixture isolates that
check. `tests-final.tap` records the original 29 PASS/0 FAIL/0 SKIP. Independent
review then found that a FIFO leaf could block `open()` before the type check.
The minimal correction adds `O_NONBLOCK`; the new bounded-child FIFO regression
and related suite record 30 PASS/0 FAIL/0 SKIP in `tests-fifo-fixed.tap`.
The first FIFO test harness used synchronous child stdin and timed out even on
its minimal stdin probe; that 29 PASS/1 FAIL receipt remains separately in
`tests-fifo-final.tap`. The corrected test uses an asynchronous original child
with a two-second bound, and exits successfully only for the expected rejection.
