# CRU21 temporary read-only guest review

This is a new, default-off candidate mode of the real workspace, not the frozen public-preview page. It is for one explicitly authorized local acceptance window. Source readiness is not authorization to enable it on MSI; this change was developed/tested in cloud only. Normal authentication and formal8787 are unchanged.

## Fixed boundaries

- Only actual branch `codex/cru21-decision-quality-p0-20261016`, clean tracked/untracked source, exact reviewed candidate HEAD, a distinct approved local main SHA, `CRU21_OWNER_PREVIEW`, actual LIVE mode and `127.0.0.1:18722` are accepted. HEAD/branch/main/clean are rechecked before each request and again before successful output. A mode flag alone cannot bypass these checks.
- `CRU21_GUEST_ENABLED` defaults off; only `0`/`1` are valid. `CRU21_GUEST_EXPIRES_AT` is an explicit UTC ISO deadline, strictly in the future and no more than15minutes away at startup. Wall and monotonic clocks both bound the original duration. Requests do not renew it; keeping the original deadline on any manual restart cannot extend that window. At expiry all new responses reject, the listener/connections close, and the guest process exits. There is no restart task or persistent lease.
- The dispatcher accepts only strict loopback socket and Host, same-origin API Fetch Metadata (`site=same-origin`, `mode=cors|same-origin`, `dest=empty`), and same-origin Origin/Referer when present. Missing Fetch Metadata, cross-site/same-site contexts, proxy headers, Authorization, upgrades and non-GET methods reject. Document navigation and static script/style loads have separate exact metadata checks. No CORS permission is granted.
- Old cookies are ignored; no login session or CSRF token is created/read/issued. Guest metadata explicitly says `authenticated:false`, `guestReadOnly:true`. Neither cookies nor a UI toggle can grant normal privileges.

**Local risk:** during this window, another program/user on the same machine can forge those headers and read the explicitly exposed market/analysis data. These controls do not authenticate local processes, prevent same-user filesystem tampering, provide market-data redistribution permission, or revoke screenshots/data already read. Do not expose or forward this listener through a proxy, tunnel or remote browser. The Owner's acceptance of the peer-local risk is required.

## Exposed surface

GET only: `/api/session`, `/healthz`, `/api/v1/dashboard`, `/api/v1/tx-chart`, `/api/v1/decision-level-watch`, `/api/v1/observed-flow`, `/api/v1/market-pulse`, `/api/v1/index-leadership`. Chart selectors are only fixed supported timeframes and modeLIVE; arbitrary dates/asOf/paths/replay/query duplicates are refused. Health emits only guest identity/expiry/safety, not normal readiness internals. Static paths are an explicit list for the real production HTML/app/chart runtime; HEAD is accepted only there. AI script initialization is replaced by a no-op for this mode.

All other routes reject, including non-whitelisted GET, login/logout, history/backtests/research, Journal, data-operations, AI status/receipts/context/models/ask/cancel/setup, OAuth and browser-runtime-proof. Every write method is refused regardless of cookie. Normal server handlers cannot receive a guest request. The real app uses a separate guest read state, not a fake CSRF/session; auxiliary tabs/actions, background requests, AI and proof POST are disabled. A banner discloses the deadline and limitations; expiry, connection closure or failed read transport hides retained guest UI. Background tabs recheck expiry when visible.

## Actual data without persistence

The normal server's cache/session/AI/formal-entry constructors and initial/recurring upstream refresh are skipped entirely. Guest mode does not initialize a session/credential store, SQLite/research reader, journal or forward writer. There is no filesystem permission change, Producer/Bridge start/restart, public upstream fetch, paid model or OAuth call.

The guest reader uses the production chart, Flow, Pulse, Level Watch and workspace builders with actual existing approved source products. Chart cacheRoot is explicitlynull (memory only). Existing market snapshot is read from the approved read root; missing products stay unavailable and never trigger refresh. Non-core research/forward/evidence panels remain unavailable rather than fabricated. No formal readiness/proof PASS is published. Application-level reads create no data/cache/session files. OS/browser temporary storage used by acceptance tooling is not a claim of zero OS disk activity.

Bridge access is only fixed `http://127.0.0.1:8790/health`, `/latest`, `/leadership` GET: no caller URL, auth/cookies, redirects or unbounded bodies/timeouts; safety flags are checked before using data. Missing/unsafe/over-budget sources stay unavailable. Filesystem roots are canonicalized, private/source overlap (including aliases/filesystem ancestors) rejects, and known read trees are checked for symlinks/hardlinks/oversized scans before loading. No raw ledger download is exposed. Limits are5000entries/depth5,64MiB per file/128MiB per guarded scan,4MiB snapshot,512KiB Bridge response. A source requiring broader access or larger scans is a blocker, not permission to relax these limits.

Every response has an explicit nested typed field schema. Unknown fields/free text, raw paths, process/lock internals, errors, credentials, Journal/AI/private context are excluded. Known interruption flags, quality, timestamps, identity, numbers and safety gates are preserved. Flow transport-only source/worker/epoch identities are process-salted HMACs so the existing UI can compare continuity without receiving raw private identifiers. Stock/industry names and non-core diagnostics are intentionally not exposed; eligible public numeric codes/ranks remain. All schema-bound numbers must be real finite numbers; missing values staynull. Oversized response arrays reject rather than silently truncate evidence.
