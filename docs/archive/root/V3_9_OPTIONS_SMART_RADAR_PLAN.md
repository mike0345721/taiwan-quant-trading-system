# V3.9 選擇權異常雷達整合計畫

最後更新：2026-07-21（Asia/Taipei）

## 目標

把現貨環境、台指期價格／量能與臺指選擇權結構串成同一條輔助決策鏈：

```text
盤後籌碼與風險環境
→ 選擇權異常履約價與攻防區
→ 盤中期貨價格、VWAP、CVD及主動成交確認
→ 風控與不交易條件
→ 研究候選；不是直接下單
```

模組名稱保留 `Options Smart Radar`，但第一階段是可解釋統計雷達，不把規則分數冒充機器學習勝率或AI可信度。

## V3.9.1：官方盤後結構雷達（已完成第一版）

- 每個履約價分開計算Call與Put異常強度0～100。
- 成交量相對20日30%、OI單日異動25%、權利金變化20%、ATM IV變化15%、到期／價位敏感度10%。
- 同履約價歷史不足5日不計成交量爆量；低基期同時受絕對成交量與絕對OI變化限制。
- 缺值不補0；依實際可用權重重算並顯示資料覆蓋率。
- 顯示Call／Put側熱度、Top 10異常履約價、標籤、量比、OI變化與可解釋原因。
- 與既有主力契約、Call／Put牆、Max Pain、1／3／5日OI圖及ATM IV／Skew共用契約與資料日。
- 只使用盤後官方資料；更新頻率不是3～5秒。

## V3.9.2：Shioaji唯讀即時雷達（等待開戶與行情權限）

逐事件保存：

- 交易所時間、接收時間、契約、履約價、Call／Put。
- 最新價、成交量、Bid、Ask及五檔。
- 可可靠辨識時才建立主動成交方向、30秒／1分鐘Delta與CVD。
- 券商提供的IV與Greeks；若自行計算，保存利率、標的、股息、時間與公式版本。
- 期貨標的價格、VWAP、開盤區間、夜盤高低與資料延遲。
- 即時OI只有資料源明確提供且口徑驗證後才使用；不得從成交量推算OI。

上線順序：連線與時間戳驗證 → 遺漏／重複事件稽核 → 日夜盤與換月驗證 → 只讀畫面 → 收集至少120日 → 正式研究。

## V3.9.3：方向確認與歷史驗證

- 雷達異常本身不等於偏多或偏空。
- Call爆量可能是買Call或賣Call；Put爆量同理。
- 方向候選至少需要權利金方向、Bid／Ask成交方向、期貨價格、VWAP、CVD和市場狀態共同確認。
- 以事件後5／15／30／60分鐘報酬、MAE、MFE、突破成功率及成本後結果評估。
- 按日切割训练／驗證，不把同一天數千筆事件當成數千個獨立交易日。
- 正向、反向、無效與樣本不足結果全部保留。

## V3.9.5：統一決策評分系統（已列入總計畫，尚未授權交易）

最終不使用一個混合分數掩蓋風險，而是同時輸出六個彼此分離、可追溯的維度：

| 維度 | 範圍 | 回答的問題 |
|---|---:|---|
| 方向分數 | -100～+100 | 經過確認後偏多、偏空或中性？ |
| 波動風險 | 0～100 | 未來是否容易放大、跳空或出現尾端風險？ |
| 選擇權異常 | 0～100 | 履約價活動相對自身歷史有多異常？ |
| 價格確認 | -100～+100 | 期貨價格、VWAP、CVD及突破是否支持方向？ |
| 可交易性 | 0～100 | 扣除成本、流動性、滑價與事件後是否值得交易？ |
| 證據品質 | 0～100 | 資料完整度、樣本數、樣本外穩定度與新鮮度如何？ |

### 新資料如何進入

1. 原始資料先經來源、交易所時間、接收時間、契約、日夜盤、換月與缺漏稽核。
2. 每個因子只進入自己的群組，例如Call成交量、Call OI與Call權利金先形成「Call活動」，不各自重複投票。
3. 高度相關指標先做群組合成或消融檢驗；RSI、MACD、均線與價格動能不得重複加成同一件事。
4. 尚未通過樣本外驗證的因子研究權重固定為0，只顯示觀察，不進正式方向分數。
5. 通過資料品質、Walk-forward、完全留出、成本、滑價與前向紙上驗證後，才可提升證據等級及正式權重。
6. 新資料每日追加，模型採固定週期重新訓練與版本化；不因單日輸贏即時亂改權重。

### 決策閘門

```text
資料品質合格
→ 市場環境可交易
→ 選擇權與籌碼形成候選
→ 價格／成交確認
→ 風險報酬與成本通過
→ 才產生紙上交易候選
```

任一核心閘門不通過，輸出「等待／不交易」，不以其他高分抵銷。最終畫面會顯示分數構成、資料時間、缺少項目、主要加分與否決原因，不只給一個看似精準的數字。

### 機器學習階段

- 第一階段：可解釋規則與統計基準，確保資料和標籤正確。
- 第二階段：Logistic Regression／樹模型等可稽核基準，預測方向、波動、突破成功與不交易風險。
- 第三階段：依市場狀態選模型的自適應選擇器，與固定規則作並行前向比較。
- 評估除AUC外，加入Brier Score、校準曲線、成本後期望、PF、回撤與不同市場循環穩定度。
- 模型輸出的機率只有通過校準後才能稱為機率；否則仍標為模型分數。

## V3.9.4：GEX／DEX／Zero Gamma研究（尚未啟動）

- 公開OI無法知道最終客戶與做市商誰買誰賣，因此只能建立假設情境，不能宣稱真實Dealer Exposure。
- 至少同時顯示「做市商全為短選擇權」等明確假設、方向敏感度及資料涵蓋。
- Zero Gamma只有在曝險方向假設與Greeks品質通過後才可顯示。
- 第一版只作加速／均值回歸環境研究，不直接加入多空分數。

## 安全與禁止事項

- 前端不保存券商帳密、憑證或API Token。
- 雷達API只讀；不建立買進、賣出、撤單或平倉端點。
- 不將Score命名為勝率、AI信心或大戶方向。
- 不以固定PCR 0.7／1.4直接判多空；門檻需按契約、到期日與歷史分布研究。
- 不把OI增加解讀成新多單，也不把Max Pain當必達目標。
- RSI、MACD及布林通道只能作待驗證基準，不因常見就自動加入決策權重。

## 驗收門檻

1. 盤後雷達資料日、契約與現有選擇權頁一致。
2. 缺少歷史、IV或權利金時不補0、不虛構方向。
3. 所有排行可追溯到原始履約價、成交量、OI與資料來源。
4. 即時版至少120個完整交易日後才比較權重與策略。
5. 通過樣本外、成本、滑價及前向紙上驗證前，`executionAuthorized=false`。
